# 列车图库 PNG → 列车番号号段映射（2611）

> **这是号码证据的反向索引，不是凭 PNG 名称推算的车组分配表。**
> 可查询某张 PNG 涉及哪些线路、哪个有出处的完整列车番号或号码区间，以及
> 工作日/休息日、时间范围、来源和审批条件。生产页面仍以既有
> `TrainNumberPngRanges.match`、`TrainVehicle` 与 Supabase 有来源的计划车型规则作最后裁决。

## 2026-11-16 映射现状

| PNG 层面指标 | 数量 | 边界 |
| --- | ---: | --- |
| 物理图库文件 | **601** | 每张均有索引项 |
| 直接进入 SQL/JS 号段目录 | **87** | 既有 421 条源规则，共 87 个不同 PNG |
| 东武/Metro 专用运行时名单图片 | **11** | 既有 Skytree/Nikko/Hibiya/Hanzomon 号码与受控车型代表图 |
| 具历史具体番号图片来源 | **3** | 小田急 198 条为 7 月来源；埼京两条为明确运营日期来源 |
| 可关联至少一种号码证据、且未被隔离的 PNG | **96** | **不是**已证明实车编组的数量，来源类别存在交叉 |
| 图像身份被隔离 | **9** | 永远不能仅因号段条目存在而直接显示 |
| 没有足够番号证据，保留待核验 | **496** | 不能从线路或文件名直接填车型/号段 |

关键是区分“**范围筛选条件**”与“**确实发布过的号码名单**”。例如一个规则标注 `1007～1144`，只能称为可能匹配的**上下界**；它不能说明每个介于两端的数字都存在列车，更不能说明这些列车使用同一辆车。

## 已建立的具体例子

- **东武 N100系 SPACIA X**：`東武鉄道_N100系_SPACIA_X.png`，东武晴空塔线及日光线的两个工作日日历名单。2026-11 工作日示例：`1007、1011、1015、1020、1026、1030、1033、1048、1123、1129、1140、1144`；必须同时符合源铁路、日期、列车种别等既有条件。代表车型，**不证明物理编组**。
- **东武 500系 Revaty、100系 SPACIA、200型 りょうもう、70090型 TH-LINER、50050型等**：同一专用匹配器已经按工作日/休息日、通勤区间/直通责任方及完整番号码返回不同 PNG；本索引追踪每个生成的图片和**全部被允许的连续精确号码岛**，不会把普通列车全部误标成特急车辆。
- **中央线 383系**：原有 SQL 正式号段 `1001M、1002M、1003M、1004M、1005M、1006M、1011M、1026M`，必须通过已存在的官方日期番号和停站序列验证，才可作为「しなの」参考图。
- **小田急 Metro 16000系 / JR E233系2000番台**：有 `Odawara` 线路的 198 条带图片历史番号来源，但时刻表来源日期是 2026-07-06，且没有独立的 11 月具体开行日期证明；索引将它们保留为**历史来源关联**，没有授权批量绘制当日图片。
- **埼京线 E233系7000番台**：`510S` 与 `759K` 的 SQL 计划图片有日期来源，仍为 `planned` 而非实际观察。
- **特殊编组或特定涂装图片**：除非号码证据明确指定该编组/涂装，不能把同一车型的普通号段复制给它。这是大量图库 PNG 没有可靠号段映射的根本原因之一。

## 查询与重建

在仓库根目录执行：

```bash
# 查询一张 PNG，显示所有直接规则、运行时名单与历史证据
node tools/build-png-to-train-number-index.cjs --lookup=N100系_SPACIA_X.png

# 检查生成结果是否和当前图库及源规则一致
node tools/build-png-to-train-number-index.cjs --check

# 原始号段权威/图库/SQL 快照更新后，重建 JSON 和 CSV
node tools/build-png-to-train-number-index.cjs --write
node --test tests/png-to-train-number-index.test.cjs
```

当查询结果为 `no_verified_number_mapping` 时，含义是“**暂时无合法的 PNG—列车番号具体对应关系**”，不是图像文件坏了；按线路展示的通用候选图和完全未确认的列车仍遵循原有渲染策略。

新增证据时应优先修改**已经负责该线路的号码规则、官方名单或现有 SQL 权威表**，再更新其来源快照与本索引；不要在本索引直接写入一种新的模型/番号配对，也不要把号段上下界当作实际服务车次名单。

## 测试与安全规则

`tests/png-to-train-number-index.test.cjs` 校验：
1. 601 张 PNG 都存在，文件名和路径没有猜测；
2. 421 条直接规则可逐条追溯；
3. Tobu SPACIA X 的精确号码岛没有填充空缺；
4. 隔离图片不会得到展示许可；
5. 小田急 7 月的号码来源不会被伪造成 11 月已核验。

`.github/workflows/verify-train-png.yml` 的现有 CI 已加入上述生成一致性和号码证据测试。这次**没有修改**实际列车身份判定、数据库或 Edge Function，也没有为了让 601 张图片“全有号段”而虚构实车分配。
